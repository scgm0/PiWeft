# 桌面对齐与限制

`PiWeft.Desktop` 使用 MewUI + NativeAOT，PiDeck 使用 Electron + React。本端口复用 pi 兼容核心，但不宣称完整桌面功能对齐。
核心协议见 [项目状态](00-status.md)，配置安全边界见 [配置管理](03-pideck-configuration-parity.md)，统计口径和基准见 [会话统计与性能](04-session-statistics-performance.md)，主题与历史渲染优化见 [桌面渲染性能](05-desktop-rendering-performance.md)。

## 视觉与主题

配色来自 PiDeck 的 `src/renderer/src/styles/foundation.css`，集中在 `AppPalette`；尺寸与字号集中在 `AppTheme`。

| 维度 | 取值（深色 / 浅色） |
|---|---|
| 背景 | app `#121212` / `#ffffff`，侧栏 `#171717` / `#ffffff`，弱化底 `#262626` / `#f4f4f5` |
| 文本 | primary `#ecece7` / `#202124`，secondary `#b8b8b2` / `#4b5563` |
| 边框 | default `#2e2e2e` / `#dfdfdf` |
| 强调色 | 近白 `#fafafa` / 近黑 `#18181b` |
| 代码块 | Markdown 代码块随深浅主题配色；工具输出使用 `#111418` 深底与 `#d1d5db` 浅字 |
| 字号 | 辅助信息 12、caption 13、control 14、正文/输入默认 16（可选 14/16/18/20/22）、title 17、brand 18 |
| 圆角 / 间距 | 圆角 4/6/8/10/12；间距 4/8/12/16/24 |
| 控件高度 | 28/32/36 |

主题切换调用 `Application.SetTheme`，不重建整棵界面或会话：

1. 长期存在的容器与按钮使用 `AppStyles` 命名样式，由 setter 按主题解析颜色。
2. `TextBlock` 不支持 `StyleName`，通过 `Tag` 角色与 `ApplyTextColors` 刷新前景色。
3. 图标缓存包含颜色，`AppIcons.RefreshAll` 更新存活控件，弱引用避免持有旧消息。
4. 消息卡片、工具、思考标题和 diff 原位换色，保留 Markdown 实例、选区、展开状态与配置草稿；分支树和 Git 不因主题变化重新加载。框架 seed 与应用配色一致，强调色使用按主题解析的 `Accent.Gray`。

`--theme-smoke` 验证 selection、picker、border、draft 和 caret，并打印切换耗时。

## 依赖与字体

MewUI 0.22.1 全部来自 NuGet。Linux 使用 X11 + MewVG，Windows 使用 Win32 + Direct2D，macOS 使用 MacOS + MewVG，按 OS/RID 选择包。不依赖本地 MewUI checkout。

Lucide 原始 SVG 内嵌，许可为 ISC。SVG tint 只处理 fill，而 Lucide 使用 stroke，因此加载时替换 `currentColor` 并将线宽调为 2.25；图标按钮附带中文提示。

正文使用 HarmonyOS Sans SC 官方静态 Regular/Bold，代码与工具输出使用 Maple Mono CN Regular，许可随包。
HarmonyOS Sans 的镜像许可与官方发布说明存在差异，分发前需核实许可；Maple Mono 为 SIL OFL 1.1。
MewUI 0.22.1 字族注册表只保留最后注册的文件，Regular 必须最后注册，否则普通正文会拿到 Bold。粗体请求交给后端处理。
界面操作使用图标或中文状态词，避免字体缺失符号引起回退混排。

## 交互与性能约束

- 会话正文与输入区居中并限制阅读宽度；默认 1060 DIP，可在外观页选择紧凑 760 / 舒适 1060 / 宽屏 1360。正文与输入字号默认 16，可选 14–22；修改立即应用、记住偏好，不替换输入框、不清空草稿或选区。短消息与折叠工具不改变整列宽度。窄窗口输入工具栏自动换行，发送/中断按钮保持固定高度和可达性。
- 消息时间线使用可变高度虚拟化，只构建视口附近控件，离开视口释放正文、Markdown 和图片；再次浏览恢复工具/思考展开状态。分支树延迟到首次打开时构建，已打开的会话直接选中标签，启动目录环境复用。核心历史仍保存在内存中，尚未实现 JSONL 分页。
- 侧栏使用 14 DIP 标题和固定时间列；标题超宽时省略，不再横向滚动把时间挤出视口，行控件由 TreeView 虚拟化复用。
- 顶部状态只显示供应商、模型、思考档和忙碌状态；用量摘要统一放到输入区下方，上下文进度和百分比仅保留一套入口。统计浮层默认“概览”，上下文容量、费用和轮次优先显示；“明细”保留全部原口径计数和提示，按快照增量更新。缺失计时仍显示 `-`，不推测旧会话指标。
- 项目侧栏可从顶栏收起；恢复时复用现有控件。侧栏状态及 200–480 DIP 宽度写入 `desktop.json`，搜索快捷键自动展开侧栏。
- 设置采用系统/配置分区和“工作区 / 维护”分类，导航独立滚动；主题卡片提供深色、浅色、系统预览。配置编辑器只在首次进入配置管理时构造，归档只在访问归档页时扫描；换肤保留外观选择与快捷键捕获控件。
- 折叠工具只创建摘要，首次展开才创建原文、图片和 diff，在视口内复用内容；移出视口后释放内容，仅记住展开状态。长输出不会预先构造文本布局。错误摘要使用错误色边框。
- 空会话页使用居中的品牌标记、标题与模型入口；侧栏去掉嵌套列表边框，用户消息采用弱化色背景，工具卡片保持轻量细边框。输入框窄屏高度缩为 56 DIP，常规窗口为 96 DIP，模型按钮弱化、发送按钮带动作图标。
- 会话搜索先即时匹配标题和首条消息摘要；正文扫描等待 220 ms，新输入与关闭窗口取消旧请求。每个候选文件实际读取不超过 512 KiB，读取缓冲复用，包含单条超长 JSONL 行；超出预算的正文不参与搜索。
- 流式期间只更新正文文本，结束后解析 Markdown；40 ms 合并刷新，复用未变化历史控件与折叠状态。
- 用户消息、思考、工具原文和流式正文使用自适应高度的只读文本控件，支持部分选择与复制，不解析原文标记。
- 代码块不嵌套纵向视口：普通滚轮移动会话列表，横向触控板和 Shift+滚轮浏览代码；保留代码高亮与复制。
- 会话、设置、Git、分支、命令面板及统计/用量视口使用逐帧平滑滚动：连续滚轮累积目标、反向输入立即转向，保留触控板小幅滚动与代码横向浏览。
- 向上浏览时立即停止追随底部，流式增长保持阅读位置；「回到最新」使用平滑动画。底部判断基于内容实际高度，内容增长追底与滚动条/键盘导航即时执行。正文使用不嵌套纵向视口的 `MarkdownPresenter`。
- 文件可拖入整个会话区：参考 VintLingo 显式设置 `Accepted` 与 `Copy`，在拖放结束前快照路径/图片；文件和目录插入草稿引用，图片后台有界读取为附件，不自动发送。
- `TextFocusScrollGuard` 只撤回文本焦点事务引起的外层位移，不影响滚轮、选择、复制与按钮键盘导航。
- 命令面板每次打开只取一份命令快照，最多显示 12 项；模型选择独立使用虚拟化供应商树，搜索覆盖全部可用模型，不截断为前 12 项。每次打开/刷新重新检查认证，输入每个字符不重读配置或偏好。
- 可用模型要求 API 已实现且能解析当前运行环境的凭据；API Key、Codex OAuth（允许待刷新）、AWS 签名凭据、Vertex ADC/token/API Key 分别按供应商真实认证路径检查。一次读取 auth.json，并按 provider/API 缓存判断；不执行命令型凭据、不发网络探测。当前模型不可用时不强行加入列表；空列表指引用户配置。`--list-models` 保留完整目录查询语义，RPC `get_available_models` 与桌面一致。models.json 的端点改动仍应用于新会话，现有会话刷新只检查启动环境对应的认证。
- 命令/模型/图片面板使用窗口级覆盖层，同一窗口只打开一个；遮罩不穿透到对话，Esc 可关闭，切换标签或销毁视图会清理浮层。
- 用户/助手消息、已展开工具结果和附件文件名支持点击图片预览。预览按窗口等比显示，点击图片不会关闭，遮罩和关闭按钮会关闭；附件删除独立操作。缩略图/预览共享图片源，Base64 身份和源均采用弱缓存，关闭预览清除源引用，换肤/重绘可复用仍存活的源。
- 跨项目会话使用自己的 cwd 环境，启动项目 MCP 不注入其它项目标签。
- 启动目录：从二进制目录启动沿用最近项目；macOS 图形外壳启动把 cwd 设成文件系统根时退回最近项目或用户主目录，终端启动与显式 `--cwd` 保持原样。
- 运行时发送按钮变为中断，保留草稿并禁用模型切换及历史修改动作。
- Markdown 链接只放行 http/https；编辑器优先 `$VISUAL` / `$EDITOR`；HTML 导出无脚本且自包含。

### 历史思考耗时与只读浏览

桌面通过 `recordInitialThinkingLevel: false` 打开会话，不追加条目或修改 mtime；真正开始对话时再记录实际级别。
CLI 默认保留 pi 启动元数据行为，RPC 字段对照测试验证消息与条目计数。

标准 pi 会话没有独立思考计时字段。`durationMs` 是整次回复耗时，不能据此推测思考耗时；本端口保留历史值。
新回复可持久化 `firstTokenMs` 与 `streamingDurationMs`，旧数据缺失时显示 `-`，计时口径见统计文档。
PiDeck 历史思考显示 0ms 的路径是未恢复 `thinkingStartedAt` / `thinkingEndedAt`，显示端回退到相同消息时间戳。
本仓库未修改该 PiDeck 路径，也不能恢复会话中从未保存的原始思考时长。

## Linux PRIMARY 选区

Linux 上选中的用户/助手原文、Markdown、代码和工具输出，以及普通输入框文本，自动发布到 PRIMARY；鼠标中键在可编辑文本的点击位置插入 PRIMARY。普通 Ctrl+C/Ctrl+V 的 CLIPBOARD 不受影响，密码框不发布文本，中键粘贴不自动发送，并且可撤销。支持与外部 Linux 应用互通。

当前 MewUI Linux 宿主是 X11/XWayland。PRIMARY 默认由进程内原生实现持有：`X11PrimarySelection` 用独立 Display 连接与专用事件线程直接实现 X11 selection owner 协议（`XSetSelectionOwner` 加 `SelectionRequest`/`SelectionNotify`/`SelectionClear`/`PropertyNotify`，只依赖 `libX11.so.6`），不启动外部程序。事件线程用 `poll` 同时等待 X 连接与 `eventfd` 唤醒：空闲时完全阻塞、不轮询，跨线程投递经 eventfd 计数合并，不会丢失唤醒。超过单个请求块的文本按 ICCCM INCR 协议分块传输：属性类型 `INCR`、format 32、值为字节数下界，块大小取握手回报的 maximum-request-size 的一半并限制在 16 KiB–1 MiB，以零长度属性结束，服务端订阅 requestor 窗口的 `PropertyChangeMask` 以追加后续块。`XOpenDisplay` 或资源创建失败时按 `xclip`、`xsel` 顺序回退外部程序；没有 DISPLAY 时才使用 `wl-copy`/`wl-paste`（需 compositor 支持，`wl-paste --primary` 仍可能不提供 PRIMARY）。全部不可用时静默保留普通剪贴板行为。原生 Wayland 后端尚未验证，纯 Wayland 且无 XWayland 时只能走 `wl-copy` 回退路径。

选区通过公开属性绑定观察，不轮询。原生实现只在自身事件线程调用 X11（不与 MewUI 的连接竞争）；回退路径用 ArgumentList 传参、不拼 shell，也不在 UI 线程做进程 IO。连续拖选合并 140 ms，最多保留一个前台 PRIMARY owner。原生写入服务 `TARGETS` 与 `UTF8_STRING`（含 `XA_STRING` 兼容读取），单次读取或写出上限 8 MiB，读取等待 2 秒。未接管全局 `XSetErrorHandler`，以免影响宿主框架的 Xlib 调用，因此异常 requestor 窗口的异步错误只由默认处理器打印、不中断服务。窗口关闭取消未落地发布并销毁自有 owner 窗口、关闭连接，X 服务器随即释放选区。异步粘贴拒绝已改动草稿、移动光标或隐藏标签的迟到结果。选区内容不会写入日志、配置或会话，只有实际发送的草稿进入会话。

```sh
xvfb-run -a -s '-screen 0 1600x1000x24' python3 tools/desktop-primary-smoke.py
```

该脚本使用独立 fixture，检查 Markdown 选区被外部 xclip 读取（此时应用自身即 PRIMARY owner，xclip 只是外部读取客户端）、外部中文多行 PRIMARY 经实际中键事件插入正确位置、CLIPBOARD 不变。截图测试分别串行启动，避免同时启动 Xvfb 的显示编号竞争。

## 日志与验证

CLI/桌面共用 ZLogger 后台文件日志，位于 `<agentDir>/logs`，按天或 4 MiB 滚动，目标保留 32 份并清理超过 14 天的旧文件。
队列上限 1024，满时丢弃而不阻塞界面；在用文件不删，退出前排空。
不记录提示词、回复、工具参数、凭据或原始 provider 响应；异常仅记录类型与堆栈。
`PI_LOG_LEVEL` 默认 Information。CLI 不污染 stdout；桌面另输出 stderr，文件日志不可写时仍可查看终端诊断。

```sh
xvfb-run -a dotnet test PiWeft.slnx
xvfb-run -a -s '-screen 0 1440x900x24' bash tools/desktop-parity-smoke.sh
xvfb-run -a -s '-screen 0 1600x1000x24' bash tools/desktop-statistics-smoke.sh
xvfb-run -a -s '-screen 0 1600x1000x24' python3 tools/desktop-workspace-smoke.py
```

`desktop-workspace-smoke.py` 默认使用 60 条折叠工具输出的独立 fixture，覆盖对话、外观、Agent 配置、MCP、720×520 窄窗口、收起侧栏、统计概览/明细、深浅空会话和 1920×1080 宽屏；设置 `PI_WORKSPACE_SMOKE_TURNS=1000` 可改用长历史。脚本检查最新回复确实可见。宽屏需要 `-screen 0 2000x1200x24`。保存截图、日志与 `results.json`。脚本需要 Python 3、ImageMagick、xdotool，通过 Linux `/proc` 读取 RSS 和 2 秒 CPU 采样。可传入场景编号分批执行，设置 `PI_WORKSPACE_SMOKE_APP` 指向 NativeAOT 可执行文件，以免把托管 Debug 构建的占用当成发布版表现。CPU 百分比以单核 100% 为基准，数据包含字体和 Xvfb/Mesa 渲染后端，不能当成所有硬件或无限历史的占用保证。

截图脚本使用独立 fixture agent 目录，不读取真实密钥。修改进程环境变量的测试必须加入 `process-environment` 串行集合。

模型筛选与图片预览改动验证：全量 852 项测试通过（2026-10-15 复核）；Linux NativeAOT 发布无警告，调试版与发布版均通过深浅主题模型弹窗、实际图片点击放大和 Esc 关闭截图演练。1000 条模型的布局测试确认 360 DIP 视口只实例化不到 30 个模型行控件；搜索覆盖全部结果。

模型筛选局部基准：Release 构建，独立目录含 20 个虚拟供应商、2000 个有凭据的模型，叠加内置目录后共 3539 条，预热后执行 5 次。逐模型调用凭据解析的对照耗时 1568.91 ms、当前线程分配 555694064 bytes；当前批量筛选耗时 91.08 ms、分配 1815064 bytes，两者返回数量校验和均为 10000。对照是相同认证筛选的逐模型读取方式，不是旧版整应用的基准；分配量是累计临时分配，不是 RSS，结果不代表网络推理或完整 UI 性能。
